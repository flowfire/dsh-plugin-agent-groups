# dsh-agent-groups · 多会话协作群

> A DSH (DeepSeek Harness) plugin that pulls multiple live sessions into one collaboration group. Each member keeps its own role and stance; the plugin relays only each round's final output on a shared timeline.

把多个**已经在浏览器中打开**的 DSH 会话拉进一个协作群。每个成员保留自己的角色与立场，插件负责：

- 只转发每个成员 **一轮结束后的最终输出**（工具调用、命令输出、中间过程全部略过）；
- 对方正在处理时**先攒着**，等它这一轮结束后，把期间所有成员的发言按时间线合并成一整份送达（统一发送，不插入打断）；
- 成员只输出 `【退出会话】` 四个字时自动离群，剩余不足两人时群自动结束；
- 提供一个时间线界面，可展开看完整文本、来源会话、轮次，并一键打开原会话。

## 安装

需要 DeepSeek Harness 0.2.x（Node 22.19+ / 24+）。

```bash
git clone https://github.com/flowfire/dsh-agent-groups.git
```

在 DSH 会话里把 clone 下来的目录安装为 bundle（agent 工具 `plugin_manager` 的 `install_bundle`，`target` 指向该目录），然后刷新页面。安装后侧边栏会出现「多会话协作群」。

插件数据默认写在 `$DSH_HOME/storages/agent-groups/state.json`，不会修改任何会话日志。

## 入口

- 侧边栏「多会话协作群」图标 → 全局面板（建群、管理群）。
- 群详情右上角「在右侧栏打开」→ 右侧栏 tab。**群聊运行时建议用右侧栏**：DSH 在任意会话产生新活动时会自动把主面板切回对话，右侧栏不会被抢走。

## 建群流程

1. 点「新建群」；
2. 勾选至少两个当前打开的会话；
3. 给每个成员起群内名字、写角色设定。默认角色模板可以直接改；
4. 选择「创建并开始」（立即唤醒成员）或取消勾选后「仅创建」（稍后再手动「重新开场」）。

> 建群表单会暂存在浏览器 localStorage，被会话活动切走再回来时能接着填。

## 提示词分两层

| 层级 | 内容 | 谁能改 |
| --- | --- | --- |
| 固定协议 | 群聊机制、只发最终结论、统一投递、静默/退出关键字、发起者身份 | 插件内部维护，界面只读展示，不能改 |
| 角色设定 | 你是谁、你的目标、你的职责与坚持 | 建群时填写，建群后也能在成员行「编辑」里改 |

固定协议会通过动态 system prompt section 注入每个成员，成员列表、角色变化会实时反映。

## 发言 / 静默 / 退出

群协议要求成员在三态里选一个，而不是用“收到，继续待命”占位置：

- **发言**：有结论、有问题、有需要其他成员知道的进展，正常输出；
- **静默**：本轮没有要说的，只输出 `【静默】`。插件不会把它写进时间线，也不会转发、不计数；成员仍留在群里；
- **退出**：任务已完成，或不清楚自己为什么还留在群里、留下也不会产生价值时，只输出 `【退出会话】`，立即离群。

协议同时禁止“收到”“继续待命”“我在”这类无信息量的占位消息。

## 发起者发言

群详情时间线下方有一个输入框。你输入的内容会以「发起者」的身份进入同一条时间线，和成员输出走完全相同的打包投递逻辑：

- 空闲成员会立刻收到；
- 正在处理事情的成员，会等这一轮结束后，把你的发言和期间其他成员的发言合并成一份时间线再收到；
- 你不需要给自己起名字，也不需要编辑角色设定；
- 发起者发言不占成员的轮次和消息上限，群暂停或结束后不能发言。

在成员的 system prompt 里，发起者会作为群里的一个固定身份出现：需要认真对待，但不替代成员自己的职责判断。

## 退出 / 暂停 / 结束

- **成员退出**：某成员本轮输出恰好是 `【退出会话】`（去掉首尾空白后完全相等）。
- **暂停**：暂停期间不再转发成员输出，也不再投递；恢复后继续。
- **结束群**：结束后成员不再收发群消息，时间线保留只读。
- **删除记录**：从插件数据中移除该群。
- **消息上限**：默认每个群 80 条成员发言，达到后自动暂停，防止两个成员无限互相“收到”。

## 数据与配置

群状态持久化在：

```
$DSH_HOME/storages/agent-groups/state.json
```

（未设置 `DSH_HOME` 时为 `~/.dsh/storages/agent-groups/state.json`。）

可以在 profile 的 `cordis.patch.yml` 里覆盖：

```yaml
- id: agent-groups
  name: dsh-agent-groups
  config:
    maxMessages: 80        # 每个群的成员发言上限
    deliveryDelayMs: 150   # 合并投递的合并窗口
    storePath: /path/to/state.json
```

## 限制

- 只接受**当前已经打开**的会话（必须有 live Agent 才能 `followup`）；未打开的会话请先在浏览器里打开。
- 同一时间一个会话只能属于一个未结束的群，避免同一份输出被广播到多个群。
- 插件只读取会话事件，不新增事件类型，也不写会话日志；群消息通过正常的 `followup` 进入成员会话，所以成员会话里能看到收到的群聊时间线。
- 子会话（subagent）不会被列出，也不能拉进群。
